## 발표 골격 — 두 축 narrative

> 서사 골격은 **맥락 인식 + Privacy-on-Edge** 두 축. 어느 각도로 찔러도 두 축으로 받아낸다.

| # | 슬라이드 | 핵심 메시지 |
|:-:|---|---|
| 1 | Hook | "비 오는 날 귀가했을 때 우리 로봇청소기가 알아서 현관을 먼저 닦으면 어떨까?" |
| 2 | 문제 | **맥락 부재** — 기존 로봇청소기는 스케줄·맵에 머무른다 |
| 3 | 포지셔닝 | **맥락 인식 + Privacy-on-Edge** — IoT 멀티센서로 맥락, 모든 추론은 디바이스에서, 클라우드로는 high-level event만 |
| 4 | 솔루션 구조 | 6-Layer + ML(위치)·Rule(맥락·점수)·LLM(설명) 분리 |
| 5 | 데모 (라이브) | 8개 시나리오 실시간 시연 — 발표의 80%를 결정 |
| 6 | 박주상 v3 설계 | ML = 사용자 위치 추정, Rule = 단기 맥락 8개 + 방별 점수 |
| 7 | 확장성·신뢰성 | JSON 30분 추가 · LLM 장애 시 룰만으로 동작 · 결정 추적 가능 |
| 8 | Closing | "가전이 맥락을 읽고, 그 결과만 클라우드에 보낸다" — 두 축 재반복 |

## 반박 대응 미리 정리

| 질문 | 답 |
|---|---|
| "맥락은 결국 카메라가 다 본다는 거?" | 카메라 없이 IoT 멀티센서(도어락·인덕션·냉장고 등) + 외부 API(날씨·캘린더)로 맥락 추론 |
| "Privacy-on-Edge는 마케팅 아닌가?" | 백엔드 API는 high-level event만 받음, raw 센서는 디바이스에서 끝남 — 코드(`backend/app/routers/`)로 확인 가능 |
| "그냥 GPT 붙인 거?" | 점수 계산은 LLM 금지, Rule-based 엔진이 결정론적으로 계산. LLM은 마지막 설명 단계만 |
| "ML 정확도는?" | 박주상 v3 설계 (`docs/CLEANING_DECISION_ALGORITHM.md`)에 따라 사용자 위치 추정 분류기를 학습 중. 학부 3주 프로젝트 범위에서 ML 일반화 가능성 검증 |
